## 与原方案相比的实现取舍

- 图片不放大。实际检测 WebP 编码 MIME；不支持时，JPEG 源回退 JPEG，可能含透明度的源回退 PNG。GIF、SVG 以及识别到的动态 WebP/APNG 保留原文件。
- client-zip 采用只存储、不压缩的流式 ZIP。大媒体导出减少复制与长任务，但目前 JS 运行时不再压缩，部分小项目的 ZIP 可能变大；后续通过 T3 移除大型依赖继续收敛体积。
- 沿用现有 `player/manifest.json` 作为运行时文件清单，删除构建期 `player-runtime.zip`，不再额外生成第二份清单。
- 状态采用一个项目 store 和局部 UI/URL 状态，避免把只属于单个窗口的状态全部变成全局状态。
- 导入逐条目生成 Blob 并释放解压数组，未采用持久化临时导入表；压缩条目的解压仍在主线程按块执行。超大压缩包的 Worker 解压可继续优化。
- 相邻视频使用 `preload=metadata`，避免为了预热而下载完整 1GB 文件。
- 未使用阿里妈妈字体的项目不携带该字体文件；字体分片与子集化留到 T3.2。导出后若通过便携 Agent 改用未携带的字体，应回编辑器重新导出。
- 显式记录 TiltedCard 的本地修改与新 SHA-256，保留 Commons Clause；更新组件来源、依赖许可和 ZIP 内许可说明，补齐 Paper 的 LICENSE/NOTICE。

## 性能数据口径

- `web/perf/baseline.json`：改动前构建，Chromium 156，1920×1080。连续输入约 200 字产生 202 次当前项目写入；导出阶段最长主线程任务 667ms。
- `web/perf/after-phase-1-2.json`：相同剧本的本轮结果；前后对照见 `web/perf/comparison.json`。

| 指标 | 改动前 | 本轮 |
| --- | ---: | ---: |
| 200 字输入的项目写入次数 | 202 | 1 |
| 输入阶段 JS 堆采样峰值 | 23.4MiB | 16.1MiB |
| 输入阶段观测到的最长长帧 | 69.2ms | 未观测到长帧 |
| 200MiB 导出耗时（含自动化等待） | 1.769s | 1.368s |
| 导出阶段 >50ms 长任务数 | 2 | 0 |
| 导出阶段 JS 堆采样峰值 | 14.9MiB | 16.0MiB |
| 十屏切换项目写入次数 | 19 | 9 |
| 十屏切换最长主线程长任务 | 282ms | 214ms |
| 十屏切换总耗时（含固定等待） | 31.204s | 32.084s |
| 编辑器主入口 JS（同一 gzip 算法） | 297.5KB | 263.1KB |

十屏切换总耗时本轮未改善，214ms 的长任务仍超过原定目标；本机软件 WebGL 环境下仍需继续分析云朵背景与转场，且必须补真机测量。表中 JS 堆不是整个浏览器内存；导出阶段 JS 堆略有上升，不能将长任务减少描述为已证明总体内存下降。主入口体积下降约 11.6%，仍未达到 200KB 目标。

- `JSHeapUsedSize` 不含完整图片解码、Blob 和 GPU 内存；100ms 采样可能漏掉瞬时峰值。新增的 `backingStoragePeakBytes` 也只覆盖浏览器暴露的部分外部存储，不能等同系统进程内存。
- 200MiB 占位视频只验证打包压力；视频兼容性与跳转使用真实 MP4 另测。
- 4000×3000 图片的多图显示版为 1920×1440；六图 RGBA 像素存储的理论量从约 274.7MiB 降至 63.3MiB，减少约 77%。这属于尺寸推算，不是整个浏览器内存的实测降幅。
- 当前自动化环境的长帧受 GPU 与浏览器运行方式影响，不能直接承诺投影机、4K 真机或 120Hz 硬件上的帧率。

## 验证入口

```bash
cd web
npm run typecheck
npm run lint
npm run test:e2e
npm run test:e2e -- --repeat-each=3
PERF_REPORT=after-phase-1-2 npm run test:perf
npm run analyze
```

性能脚本独立运行，不与功能回归并发，避免 GPU 争抢；常规 E2E 自动跳过它。服务器协议测试包含在 `test:e2e` 中，也可单独 `npm run test:server`。

WebKit 验证用于 Safari 引擎兼容性补充，不等同真实 Safari/iPhone 的最终验收。本机 WebKit 无痕上下文写入 Blob 会报 UnknownError，普通持久会话正常；最小复现见 `web/perf/webkit-storage-probe.json`。该结果与 [WebKit 已记录的 Blob/IndexedDB 问题](https://bugs.webkit.org/show_bug.cgi?id=188438)相符。编辑器测试使用每例独立的普通配置目录，便携播放器仍使用无痕上下文并验证不创建数据库。没有通过在测试中替换应用存储来规避问题。

## 本轮验收结果

- `npm run typecheck` 与 `npm run lint` 通过；保留已有组件/refs 提示。
- Chromium 全量回归 26 项通过，1 项性能用例按设计跳过；性能用例单独运行通过。
- 保存、撤销、mesh/grain 背景与收尾预览共 5 项重点场景重复三次：15 项通过；匹配到的性能用例仍按设计跳过。
- 服务器协议单测通过，包含单段、开尾、后缀、越界/非法范围、HEAD、缓存和方法限制。
- WebKit 4 项通过：保存与 Agent 并发、大图三档、保存失败恢复、ZIP 播放器离线运行和真实 MP4 跳转。编辑器使用普通会话，播放器使用不依赖数据库的无痕会话。
- 包分析命令执行成功；报告在 `web/dist/bundle-report.html`。分析构建有 Tailwind sourcemap 提示，不把它当成业务运行失败。
