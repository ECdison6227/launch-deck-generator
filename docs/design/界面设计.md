# 发布会演示工具：首轮界面设计

日期：2026-10-15。阶段：结构方案，未渲染、未验证实际视觉，未进行视觉评分。

依据：[BRD](../BRD.md)、[组件调研](../组件复用调研.md)。设计 Agent 已参与结构与组件能力核对，本稿由主 Agent 汇总落盘。用户已确认简洁可视化编辑、浏览器演示、现成布局与内容替换；所有组件只做组合。

## 1. 体验方向

用户进入页面后直接看到当前演示页。主要动作是“修改这一页”和“开始演示”，工具区不使用大幅宣传文字。借鉴 Hark 的柔和背景与悬浮材质，编辑器控件保持稳定、清晰，演示内容使用适合大屏的字号。

| 项目 | A：舞台工作台（推荐，尚未确认） | B：舞台优先抽屉（备选） |
| --- | --- | --- |
| 结构 | 左侧页面列表、中央舞台、右侧当前属性 | 中央舞台、底部页面条、按需打开属性抽屉 |
| 优点 | 页面顺序、当前内容和设置同时可见，初次制作更直接 | 舞台更大，适合持续微调一页 |
| 代价 | 小屏上舞台可用宽度减少 | 设置反复开关，跨页编辑不够直接 |
| 适用 | 首版桌面编辑器 | 窄屏或专注预览模式 |

推荐 A，以页面制作效率为依据；两种结构均使用同一套现成组件。A/B 是结构文字对比，尚未制作可视化对比页，不将其视为用户已选定的视觉方向。

## 2. 编辑态线框

```text
┌ 演示名称 / 保存状态 ────────────── 预览当前页 ── 开始演示 ┐
│ 页面列表       │ 当前页 16:9 舞台                │ 当前页属性 │
│ 01 大字        │                                 │ 布局       │
│ 02 主图        │        标题、图片、视频、         │ 内容       │
│ 03 图文        │        表格或卡片的组合           │ 背景       │
│ ＋添加页面     │                                 │ 出场       │
│                │ 页内内容顺序 / 添加内容入口     │            │
└─────────────────────────────────────────────────────────┘
```

顶部只保留项目级动作。左侧使用现成 Sidebar / ScrollArea / Button；中央使用 AspectRatio 维持舞台比例；右侧使用 Tabs、Label、Input、Textarea、Select、Slider 等现成控件。优先固定 shadcn 的 Radix 分支，不混用多套基础交互体系。

建议桌面三栏：页面列表约 176–208px、属性区约 288–320px，中间区域占剩余空间。具体尺寸只是待渲染验证的起点；较窄视口把属性区转入现成 Sheet，舞台始终等比缩放。工具控件和舞台不使用同一套字号缩放。

## 3. 五类内容与六类布局

| 布局 | 组合的内容 | 用户主要调整 |
| --- | --- | --- |
| 大字 | 标题、可选短句 | 文字、对齐、字号预设、出场顺序 |
| 主图 | 图片、可选标题 | 替换图片、contain/cover、留白比例 |
| 图文 | 文本与图片 | 图文左右关系、比例预设、出场顺序 |
| 视频 | video、可选标题 | 替换文件、封面、静音、循环 |
| 卡片组 | 现成 Card 或 TiltedCard 承载图文 | 内容、数量预设、材质与现成效果 |
| 表格 | 现成 Table、可选标题 | 数据、表头、重点行列、整体入场 |

这些是官方组件和示例的应用组合配置，不是另写基础组件或布局引擎。卡片属于容器，可承载文字与图片；背景属于页面配置。内容容量以模板支持的槽位为准，首版不出现自由拖动控制点。

## 4. 关键操作与状态

| 状态/操作 | 界面处理 | 组件与接线 |
| --- | --- | --- |
| 添加页面 | 选择布局，创建并选中新页 | Dialog / Select / Button，绑定页数据 |
| 添加图片 | 空槽位提供文件选择；粘贴后立即预览 | 原生文件输入、Clipboard 事件、现成图片容器；这是素材接线 |
| 编辑文字 | 属性区输入，舞台同步反映 | Input / Textarea，绑定同一份内容数据 |
| 编辑表格 | 表格数据面板中编辑单元格或粘贴二维数据 | Table / Input；不制作电子表格工具栏 |
| 调整背景 | 预设色板、颜色值、速度；只显示当前背景支持的参数 | Select / Input / Slider；Paper Shaders props |
| 调整出场 | 选择“随页出现”或“按点击出现”，顺序用上下移操作 | Select / Button；reveal 配置和 Fragment index |
| 删除页面 | 明确当前页名称和后果，再执行 | AlertDialog；页数据操作 |
| 素材缺失 | 保留槽位与文字，提供重新选择入口 | Alert / Button；不显示虚假成功 |
| 保存失败 | 保留编辑内容，显示失败及重试入口 | Alert / Button；存储错误接线 |
| 保存中/已保存 | 顶部显示真实状态 | 状态文本；以持久化结果为准 |

只有现成组件没有覆盖的应用数据、事件与生命周期接线可以自行编写。不自行实现按钮、文件选择器 UI、卡片物理或播放器控件。

## 5. 演示态与动作

```text
┌──────────────────── 浏览器全屏 ──────────────────────┐
│                  常驻动态背景                         │
│               当前页内容 / 页内步骤                    │
│                                                      │
└──────────────────────────────────────────────────────┘
```

演示时内容占据视口，编辑面板退出画面。采用 reveal.js 官方 React 的 Deck / Slide；键盘翻页与页内步骤由框架负责。退出后返回原编辑页，媒体离页暂停。

三类核心动作分别使用既有能力：切页采用内置 fade；点击逐项展示采用 Fragment 的 fade-up；图片卡片指针倾斜采用 TiltedCard。Fragment 不等于自动错峰出场，TiltedCard 不等于自动漂浮。整页进入的精细节奏和其他文字预设留待实际组合验证，不手写时间轴补齐。

背景在内容层之后保留同一实例；换页不重新创建同一背景。默认采用 Paper MeshGradient，云朵以 Vanta CLOUDS 作为候选。Stack / CardSwap 仅为后续可选效果，常规正文和表格保持静止。

## 6. 配色、材质与验收

建议编辑器采用中性浅底、清晰边线、一种操作强调色；演示舞台的配色独立，允许 Hark 式深色氛围和当前 index 的浅色柔光。普通 Card 优先清楚承载内容，透明度和描边通过主题配置调整。字体用系统中文无衬线栈起步，后续如引入字体则使用明确可用的字体资源。

已确认：浏览器、可视化、模板槽位、五类内容、组件组合约束。建议项：三栏结构、默认背景与默认切页方式。未验证：实际视觉、投影可读性、候选依赖兼容、视频与背景并行性能、素材持久化与演示状态恢复。
