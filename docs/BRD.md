# 发布会演示工具 BRD

版本：v0.1 讨论稿。日期：2026-10-15。

已确认：简洁可视化编辑、浏览器现场演示、选择现成布局后替换图文并调整比例与出场顺序、全部采用现成组件并只做组合。本文将这些确认与建议默认值分别标记；可继续讨论调整，不代表完整软件已经实现。

## 1. 业务目标

让需要发布、介绍或讲解产品的人，使用少量内容类型和统一的动态视觉语言，快速制作一套可由自己控制节奏的浏览器演示。

用户提供每页的图片、视频、文字和少量表格，通过界面选择布局、背景配色与现成动效，即可全屏讲解。产品价值集中在内容呈现、动作节奏与使用简单。

## 2. 用户与场景

- 核心用户：独立制作发布会、产品介绍、项目汇报的人。
- 编辑场景：在桌面浏览器粘贴图片、填写文字、添加视频或表格，预览后调整。
- 演示场景：连接大屏或屏幕共享，使用方向键、空格或翻页器控制讲解。
- 交付场景：建议支持把内容和素材打包，在另一台电脑的浏览器播放。

## 3. 范围与设计原则

### 用户明确约束

1. 第一版提供简洁可视化编辑。
2. 主要交付形式为浏览器演示，保留动态背景和卡片效果。
3. 所有基础控件、背景、卡片效果、入场和翻页机制采用现成组件。应用只做组合、配置、数据绑定和接入。
4. Hark 是效果研究参考；已有可复用组件优先于重新实现相似效果。
5. 每页先选现成布局，再替换图文、调整比例与出场顺序；第一版采用模板与内容槽位。

### 建议默认值，可在讨论中调整

1. 16:9 固定演示画布，默认按 1920×1080 的设计坐标等比适配。
2. 布局采用已确认的模板与内容槽位；建议在各模板支持的容量内增删内容，并提供比例预设。
3. 编辑为本地单用户模式；保存、导入、打包优先于账号和云端协作。
4. 整套演示设置一个默认背景，单页可以覆盖背景类型或配色；同类背景切页时持续运行。
5. 内容默认随页面进入，也可设置为按点击依次进入；自动轮换的卡片单独启用。
6. 默认背景采用现成渐变组件，云朵作为第二类背景候选；实际效果需对比样张后确定。

## 4. 内容类型

| 类型 | 第一版能力 | 业务边界 |
| --- | --- | --- |
| 大字/文本 | 标题、短正文、字号预设、对齐、颜色、强调；支持多个内容项 | 优先发布会短文案，不增加复杂排版工具 |
| 图片 | 剪贴板粘贴与文件选择、contain/cover、比例与圆角预设、替换 | 先复用现成显示与上传能力，不增加图片绘制或修图 |
| 视频 | 本地文件、封面、播放/暂停、静音与循环设置 | 默认点击播放；离开页面停止播放，避免跨页出声 |
| 表格 | 填写单元格、粘贴二维数据、增删行列、表头与重点行列样式 | 面向少量对比信息；不做电子表格计算引擎 |
| 卡片 | 标题、描述、图片等内容组合；普通、半透明与可选倾斜/堆叠预设 | 卡片是内容容器；效果受现成组件能力约束 |

背景是页面或整套演示的独立配置，不作为第六种需要自由摆放的前景对象。

## 5. 核心流程

1. 新建演示并设置名称、全局配色和背景。
2. 添加一页，选择布局，例如大字、主图、图文、视频、卡片或表格。
3. 在对应槽位粘贴或选择素材，填写文字和表格。
4. 为内容选择现成入场预设与出现顺序，预览当前页。
5. 通过缩略图切换页面，复制、删除或调整页序。
6. 保存项目，进入演示，按讲解节奏逐项展示和翻页。
7. 退出后回到当前编辑位置；必要时导入或导出完整项目。

## 6. 功能需求

核心版本先完成编辑、保存和现场播放。F11、F12 是便于分享的后续建议，尚未由用户确认，不作为首个可用版本的门槛。

| 编号 | 功能 | 第一版要求 |
| --- | --- | --- |
| F01 | 页面管理 | 新建、复制、删除、重排、选中；显示缩略图与页序 |
| F02 | 简洁编辑 | 中央预览、页面列表、当前页/内容属性；主要操作可直接找到 |
| F03 | 五类内容 | 完成第 4 节的内容输入与替换；空内容有明确添加入口 |
| F04 | 布局 | 提供至少大字、主图、图文、视频、卡片组、表格六类预设；组合现成布局原语 |
| F05 | 背景 | 配色预设、自定义颜色、速度与暂停；仅展示当前组件实际支持的参数 |
| F06 | 动效 | 至少淡入、轻移入、依次出现；整页与逐项触发可选；直接采用组件预设 |
| F07 | 卡片效果 | 基础卡片与至少一种现成灵动效果；倾斜与自动轮换不得混为一个开关 |
| F08 | 演示 | 进入/退出、前进/后退、跳页、页内步骤；键盘行为采用现成演示框架 |
| F09 | 视频生命周期 | 离页暂停；返回后的续播/重播行为明确；有声自动播放失败时仍有播放入口 |
| F10 | 保存 | 文本、页面配置与素材持久化；刷新后恢复；保存失败可见且不清空当前内容 |
| F11 | 搬运（扩展建议） | 项目数据与媒体一同导出/导入；不依赖临时 blob URL 或原电脑绝对路径 |
| F12 | 播放包（扩展建议） | 资源本地化、离线播放；明确打开方式，不以依赖联网 CDN 的页面冒充离线包 |
| F13 | 预览一致 | 编辑预览和全屏播放读取同一份页面数据与内容组合，避免维护两套排版 |

## 7. 动效规则

- 背景是缓慢氛围；主要信息出现后保持稳定，表格和长正文不持续漂浮。
- 同一种元素默认采用一致的入场方式，演讲者可按步骤触发。
- 指针倾斜为可选效果；即使讲解时不移动鼠标，信息与出场也完整。
- 页面切换与内容入场由现成演示框架协调，避免多个引擎争用同一节点的 transform。
- 卡片内部倾斜与外层入场可以组合，但分别由现成组件拥有各自节点。
- 不为获得与 Hark 完全一致的翻牌效果而补写手势、mesh、spring 或 shader。
- 找不到适配组件时，记录缺口并选择现成替代效果；不得静默改成自研组件。

## 8. 技术方向

技术依据与官方来源见 [组件复用调研](组件复用调研.md)。以下是建议组合，安装验证后锁定具体版本。

| 能力 | 推荐方案 |
| --- | --- |
| 工程 | React + TypeScript + Vite |
| 编辑控件与容器 | shadcn/ui；选定同一基础交互体系；Lucide 图标 |
| 浏览器演示 | reveal.js + 官方 `@revealjs/react`，使用 Deck / Slide / Fragment / Auto-Animate |
| 默认动态背景 | `@paper-design/shaders-react` 的 MeshGradient，补充 Warp 或 GrainGradient 中的一种 |
| 云朵背景候选 | Vanta CLOUDS + 兼容的 Three.js；先验证，不默认使用任意最新版 Three.js |
| 卡片效果 | React Bits 的 TiltedCard 或 Stack；按代表页选择，避免首版安装全部效果 |
| 视频 | 浏览器原生 video 与演示框架媒体行为 |
| 表格 | 现成 Table 和输入控件；二维数据解析只作为应用接线逻辑 |
| 持久化与打包 | Dexie / IndexedDB 保存页面和素材，JSON 保存可搬运的内容结构，fflate 生成 ZIP；安装与资源打包方式需集成验证 |

第一版不需要服务器来渲染页面。应用可以本地运行或静态部署；账号、云端文件托管不是当前前置条件。

“只做组合”的可接受代码：页面数据模型、组件映射、事件与生命周期适配、配色和布局配置、素材索引、保存和导出。禁止自行实现基础控件、拖拽缩放引擎、播放器 UI、shader、手势和动画物理系统。

## 9. 质量与验收

以下是验收目标，不是当前已通过的测试结果。

1. 建立一套至少 6 页的代表性演示，覆盖五类内容与一个组合页。
2. 能粘贴图片、修改标题、替换视频、编辑表格并即时预览；刷新后素材与配置仍可恢复。
3. 点击与键盘均可演示，逐项出场、前后翻页和跳页保持正确状态。
4. 同一动态背景翻页不中断、不闪白；快速切页后没有残留媒体声音或多余动画实例。
5. 1920×1080 演示和常用桌面编辑视口中，大字、表格与素材没有遮挡、意外裁切；演示画布等比适配。
6. 在记录了硬件、浏览器和素材规格的环境中，验证视频与背景并行效果；目标稳定 30fps 以上，力争 60fps。未达到时使用组件现有质量参数或静态背景模式。
7. 如果纳入 F11/F12 扩展，在另一台电脑断网验证播放包；资源不遗漏，打开方式清楚。
8. 每个视觉/交互组件有上游地址、版本或 commit、许可和本地修改说明；不得用“参考某库”掩盖自写实现。

## 10. 第一版暂不纳入

- 可编辑 PowerPoint 导出与 HTML 动效的双向转换。
- 复杂时间轴、任意关键帧、自定义 shader、自由绘图与修图。
- 多人协作、账号体系、云端素材管理、支付和模板市场。
- AI 自动写整套发布会、自动配图、远程多人控制。
- 复杂 Excel 计算与数据分析图表系统。

## 11. 待继续讨论

这些问题先采用上文默认值，不将尚未提供的信息写成用户确认。

| 事项 | 当前建议 |
| --- | --- |
| 当前 index 背景 | 保留原件，作为参考与既有资产候选；默认实现用可追溯第三方背景 |
| 云朵最终视觉 | Vanta CLOUDS 作为已找到的候选，通过实际画面对比决定 |
| HALOCARD 唯一仓库 | 尚未确定；不阻塞采用已找到的现成卡片组件 |
| 跨页调色方式 | 能否连续插值取决于组件原生能力；至少实现稳定切换，不手写 shader 过渡 |
| 演示规模与设备 | 暂按桌面单用户、常见 1080p 演示设计，实际页数与视频大小再校准 |

## 12. 交付顺序

1. 本轮：需求讨论、组件证据、BRD v0.1 与设计交接。
2. 设计 Agent：先制作工作区界面方案与组件映射，明确每项来自哪个现成组件；展示编辑态和演示态的关键状态。
3. 方向收敛后：先做六页代表性演示，验证背景、入场、卡片和视频组合，再扩展完整编辑与打包流程。

设计阶段不会把未验证的组合写成已经完成的产品能力。
