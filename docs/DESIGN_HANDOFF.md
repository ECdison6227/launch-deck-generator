# 设计 Agent 交接

当前阶段：需求与组件调研后，制作设计方案；尚未进入完整产品开发。

先读 [BRD](BRD.md) 和 [组件复用调研](组件复用调研.md)。用户已明确选择简洁可视化编辑与浏览器演示，要求全部采用现成组件，只做组合。

## 本次设计任务

产出 `docs/design/界面设计.md` 与 `docs/design/组件映射.json`，用于下一轮讨论和后续实现。优先把操作流程和组件归属说明白，不启动完整应用、不修改现有 `index.html`、不安装产品依赖。

设计至少覆盖：默认编辑界面、添加图片与文字、编辑表格、设置背景与动效、全屏演示、缺失素材与保存失败。可以用 Mermaid/文本线框说明布局；只交付设计说明时如实标记“未渲染、未验证视觉”。

## 设计约束

- 画面主角是当前演示页。工具栏、缩略图和属性面板为编辑服务。
- 参考 Hark 的空间和材质，但按发布会字号、内容密度重新组织，不复制聊天布局。
- 演示内容支持文字、图片、视频、表格、卡片；背景独立保留。
- 用户已确认布局采用现成模板与内容槽位，替换图文、调整比例和出场顺序。自由拖放不在第一版。
- 分清半透明卡片、鼠标倾斜、堆叠切换与入场，分别指向已有组件。
- 控件使用现成组件；不得发明一套需要后续手写的基础控件或特效。
- 同一能力选一个主实现，备选单独标记；不把候选列表当成全部必装依赖。
- 颜色、文字尺寸、间距和圆角采用主题配置；只组合和配置，不重写第三方底层算法。
- 用户尚未选定具体界面视觉方向。先提供少量可比较的方向说明与推荐，不把推荐写成已确认。

## 交付内容

1. 产品定位、主要操作、推荐结构与另一种结构的简短比较。
2. 编辑态和演示态线框，说明 16:9 舞台如何适配桌面工作区。
3. 六类布局与五类内容的关系，说明“卡片”作为容器如何承载图文。
4. 背景、内容入场和卡片交互的组件来源及触发方式。
5. 关键状态与用户可见反馈，包含撤回/删除等容易误操作的处理建议。
6. 确定项、建议项、未验证项分开列出。

组件映射 JSON 至少包含 `capability`、`primary`、`sourceUrl`、`reuseMode`、`status` 和 `notes`。不要把未知的 HALOCARD 仓库编造成确定来源。
