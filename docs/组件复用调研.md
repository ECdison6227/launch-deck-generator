# 发布会演示工具：组件复用调研

调研日期：2026-10-15。本文区分本地证据、官方组件能力与选型建议；没有进行候选库集成、性能实测或完整运行验证。

## 已确认的产品方向

用户选择第一版采用简洁可视化编辑：粘贴图片、填写文字、选择布局和动效；使用浏览器现场演示。排版方式已确认：先选现成布局，再替换图文、调整比例与出场顺序。所有界面与效果采用现成组件，只做组合和配置。用户提到的 hub 指 GitHub；HALOCARD 未提供唯一仓库地址，不据同名搜索结果认定其身份。

## 1. Hark 能借鉴什么

已阅读调研目录中的 README、主报告、设计分析、卡片代码分析和运行实测，并查看图片栈展开、收起截图。

| 内容 | 已有证据 | 对本产品的处理 |
| --- | --- | --- |
| React | 保存的 `BNXT4JyW.js` 包含 react-dom renderer 标识，版本字段为 19.2.4 | 说明 Hark 使用 React；不能由此决定本产品的精确版本 |
| Radix UI 基础能力 | 多个保存脚本包含 Radix Primitive 与 Dialog 辅助文本标识 | 可以采用相同类别的成熟基础库，不提取 Hark 的业务封装 |
| Streamdown | 卡片报告与 `BT2rDYKB.js` 中的组件标识、文本渲染调用链相互印证 | 属于流式 Markdown 能力；当前五类内容展示不依赖聊天式渲染，第一版不引入 |
| 半透明卡片材质 | 透明填充、独立描边、连续曲线圆角；不同容器并非都使用背景模糊 | 借鉴材质关系，用现成 Card 组件及主题参数表达 |
| 图片堆叠、拖动翻动、展开到网格 | 调研保存了专门的手势、布局测量、spring、mesh 和 DOM 搬移逻辑 | 未发现独立公开组件包的证据；选择现成相近组件，不逐行移植 |
| 动态天空 | 完整 wallpaper HTML 与 GLSL；涉及天气、时间、调色、后处理 | 第一版只需要可控氛围，不需要整套天气天空系统 |
| Motion 类动画实现 | 部分脚本包含动画值与播放器结构 | 仅凭这些结构不足以确认完整依赖归属，不写成“全部由 Framer Motion 实现” |

本地来源：[主报告](../../hark-ui-reserch/reports/hark-chat-analysis.md)、[设计分析](../../hark-ui-reserch/reports/design-analysis.md)、[卡片代码分析](../../hark-ui-reserch/reports/card-code-analysis.md)。这里的相对路径跨项目不适合作为发布链接，原目录为 `/Users/cjr/Projects/hark-ui-reserch`。

结论：Hark 可提供视觉和交互参考。现有证据不能支持“它的卡片、shader 全部有现成第三方组件可直接安装”，也没有建立这些已发布业务代码的复用授权。

## 2. 当前 index.html 的背景是什么

当前工作区只有一个 `index.html`，标题为“云光实验室 · 轻盈烟雾与柔光背景”。文件在第 102 行起内置 `PastelAtmosphere` 类及顶点、片元 shader，没有外部组件导入。

- 六种模式：云雾光晕、流光以太、丝绸柔光、漫游烟雾、晨曦极光、柔粒渐变。
- 已有四个颜色输入以及密度、速度、光感、明亮度参数。
- 已有 `setOptions`、`setPaused`、`snapshot`、`destroy` 调用接口及 Canvas 2D 降级分支。
- 模式名称与一些组件站名称相似，不能据此认为它来自 React Bits。
- 是否允许把这份已存在的实现当作既有资产直接复用，可以单独决定；直接调用既有实现与重新编写 shader 是两件事。

建议保留原文件作为效果参考。若严格优先采用可追溯第三方组件，第一版使用 Paper Shaders；不同时维护两套同类背景引擎。当前文件没有被修改。

## 3. 背景候选

| 候选 | 现成能力 | 适用性与边界 | 建议 |
| --- | --- | --- | --- |
| Paper Shaders `MeshGradient` | 多色渐变、扭曲、旋涡、速度、颗粒、帧与像素预算参数 | 适合贯穿多页的柔和渐变，React 包直接提供组件 | 默认背景候选 |
| Paper Shaders `Warp` / `GrainGradient` | 流体或烟雾状色场、柔和程度、颗粒参数 | 可以从同一库补充第二种氛围，具体效果需看实样 | 先选一种补充，不全部堆入第一版 |
| React Bits `Grainient` / `Silk` / `Aurora` | 渐变、丝绸、极光等现成效果，支持 registry 安装 | 效果明确；不同组件的依赖和可调参数不同，不能承诺统一支持任意颜色/参数 | 对比与备选 |
| Vanta `CLOUDS` | 天空、云、阴影、太阳相关颜色与速度 | 已找到的开源云朵候选，不能确认就是用户记忆中的项目；需 Three.js | 云朵选项优先验证 |
| Vanta `CLOUDS2` | 另一种云层视觉、天空/云/光照颜色与速度 | 默认还引用 `./gallery/noise.png`；保存的 master 树里没有该纹理 | 备用，补齐资源与验证后才能启用 |
| Vanta `FOG` | 雾感、颜色、速度等 | 适合柔雾背景，需和渐变方向做实际画面对照 | 次选 |
| Hark wallpaper | 完整动态天空及天气系统 | 功能远超需求，且未建立为可独立安装复用组件的证据 | 参考，不作为第一版依赖 |

已把 Vanta 的云朵/雾源文件、构建产物、公共基类、README 与许可下载到 [upstream/vanta](research/upstream/vanta/)，固定 commit、原始 URL 和 SHA-256 见 [snapshot.json](research/upstream/vanta/snapshot.json)。这是调研快照，未接入软件；不等同于可单独运行的演示。

官方来源：[Paper MeshGradient](https://shaders.paper.design/mesh-gradient)、[Warp](https://shaders.paper.design/warp)、[GrainGradient](https://shaders.paper.design/grain-gradient)、[React Bits](https://reactbits.dev/)、[Vanta 仓库](https://github.com/tengbao/vanta)、[Vanta 云朵预览](https://www.vantajs.com/?effect=clouds)。

## 4. 卡片与动效候选

“悬浮”需要拆成可独立选用的能力。浮在背景上的材质、鼠标倾斜、自动漂浮、堆叠轮换、点击后入场，不是同一个效果。

| 需求 | 现成来源 | 取舍 |
| --- | --- | --- |
| 普通文字/图片信息卡、半透明容器 | shadcn/ui `Card`；主题参数调整填充、边框、圆角 | 作为常规卡片，保持内容清晰 |
| 指针跟随轻微倾斜 | React Bits `TiltedCard`，或 Aceternity `3D Card Effect` | 主选一个；不是自动漂浮，也不是 Hark 翻牌的等价实现 |
| 图片堆叠与拖动切换 | React Bits `Stack` | 接近 Hark 的图片栈表达；不承诺完全相同的分片翻牌 |
| 卡片自动轮换 | React Bits `CardSwap` | 适合可选展示页；讲解正文默认不自动轮换 |
| 大字从模糊到清晰 | React Bits `BlurText` | 作为进阶预设候选；进入、重播与回退需和演示框架验证 |
| 点击后逐项出现 | reveal.js `Fragment`，内置 `fade-up` / fade 等 | 第一版的基础入场方案；演讲者掌握节奏 |
| 翻页与跨页同对象过渡 | reveal.js transition / `Auto-Animate` | 直接使用既有能力；不编写自定义转场引擎 |

官方来源：[TiltedCard](https://reactbits.dev/components/tilted-card)、[3D Card Effect](https://ui.aceternity.com/components/3d-card-effect)、[Stack](https://reactbits.dev/components/stack)、[CardSwap](https://reactbits.dev/components/card-swap)、[BlurText](https://reactbits.dev/text-animations/blur-text)、[Fragments](https://revealjs.com/fragments/)、[Auto-Animate](https://revealjs.com/auto-animate/)。HALOCARD 未确定唯一仓库，当前不作为已选依赖，也不阻塞相同需求的选型。

## 5. 推荐技术组合

| 层 | 建议 | 自有代码边界 |
| --- | --- | --- |
| 前端工程 | React + TypeScript + Vite | 页面组合、数据绑定、构建配置 |
| 编辑器控件 | shadcn/ui，基础交互选定一个底层体系；图标统一 Lucide | 调用现成按钮、面板、输入、滑块、上传相关控件等，不写同类基础组件 |
| 浏览器演示 | reveal.js + 官方 `@revealjs/react` | 把页数据映射到 `Deck` / `Slide` / `Fragment`；处理事件接线 |
| 背景 | Paper Shaders 为默认，Vanta CLOUDS 为云朵候选 | 配色预设、参数映射、生命周期适配；不写 GLSL |
| 内容卡与可选效果 | shadcn Card + React Bits 选中的单个卡片效果 | 填入真实内容与样式参数，不写手势和物理算法 |
| 展示表格 | shadcn/ui `Table` | 表格数据与现成单元格控件绑定；不增加无关分页、筛选引擎 |
| 视频 | 浏览器原生 video + reveal.js 媒体生命周期 | 资源绑定、封面与现成播放行为；不开发播放器控件 |
| 本地保存 | Dexie / IndexedDB | 保存页面数据和素材 Blob，不把视频塞入 localStorage |
| 项目打包 | fflate | 组合 JSON 与媒体文件；播放包打开方式仍需集成验证 |
| 后续如需自由拖放缩放 | `react-rnd` | 用户已确认第一版用模板槽位，首版不引入 |

官方 reveal.js 文档目前提供 React 包的 `Deck`、`Slide`、`Fragment` 与事件接口。以上是文档层选型，尚未进行版本组合安装验证；实际安装时固定相容版本。

工程与数据层官方来源：[Vite](https://vite.dev/guide/)、[Dexie](https://dexie.org/docs)、[fflate](https://github.com/101arrowz/fflate)、[Lucide React](https://lucide.dev/guide/react)。

许可记录：Paper Shaders 为 Apache-2.0；Vanta 仓库声明 MIT。React Bits 当前为 MIT + Commons Clause，不能写成纯 MIT；其许可限制将组件本身作为组件包等再分发。本产品按应用接入，并保存所用组件版本与许可。详见 [Paper LICENSE](https://github.com/paper-design/shaders/blob/main/LICENSE)、[Vanta LICENSE](https://github.com/tengbao/vanta/blob/master/LICENSE.md)、[React Bits LICENSE](https://github.com/DavidHDev/react-bits/blob/main/LICENSE.md)。

## 6. 需要用实样验证的事情

1. 大字、图片、视频、表格、卡片各一页，加一页逐项入场组合。
2. 背景独立于页内容保留，翻页不重建同一背景实例；调色是否支持平滑变化以选定组件为准。
3. 前进、后退、跳页、快速连续翻页后，入场状态与媒体播放仍正确。
4. 1080p 浏览器演示同时播放视频和背景时的实际帧率；不承诺全部设备固定 60fps。
5. 打包后断网打开，图片、视频、字体与 CLOUDS2 纹理等资源是否齐全。

调研结论：现成组件可以覆盖第一版主要需求。真正需要开发的是编辑数据、素材持久化、页面组合和播放接线；不能把“只做组合”理解成完全没有应用逻辑。
